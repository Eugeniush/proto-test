Ask AI — loading state

Step between sending the request and the answer. Same layout as the answer (header + 3 cards) so nothing jumps when results arrive.

1 · Loading (0–15 s)

Header in the answer’s place with an animated label. Skeleton cards mirror the real card: title, time · customer, avatar + name. Send is disabled. No actions yet.

Rules
• 0–1 s: nothing changes visually (avoid flicker), but the request can’t be sent twice.
• 1–15 s: state 1. One loader only — the header label; the send button is just disabled, no spinner.
• 15 s+: state 2 with hint + Cancel. Timeout at 90 s → error in the same place with “Try again”, query kept in the input.
• Skeleton count = 3 cards (typical answer). Real answer replaces the skeleton in place.
• Respects “reduce motion”: animations stop, skeleton stays static.

Error cases (same alert, different text)
• Timeout (most common, shown above): “The request timed out. Check your connection and try again.”
• No internet (browser offline): “You’re offline. Reconnect and try again.” — show immediately, don’t wait 90 s.
• Server error (5xx): “Something went wrong on our side. Try again in a moment.”
• Try again = resend the same query (back to state 1). Dismiss = close the answer, keep the query in the input.
• Never show raw error codes to the user; log them for support.
